安卓开发知识地图 · 本项目缺口对照 · Java 方向学习路线

对象：智能选课系统（com.example.myapplication003，Java + XML + 裸 SQLite）。目标：从"能跑起来"走到"独立开发、上架、求职"。
本项目 = 一个及格的大作业 缺 2 个完整体系 上架知识 0 基础 Java 路线可行
先说结论。这个项目让你真正摸过的是：四大组件里的两个（Activity / Fragment）、XML 布局、RecyclerView 的基础用法、多语言资源、以及用 SQLiteOpenHelper 手写增删改查和一条 inner join。

但你现在的写法，是 2015 年前后「大作业式」的 Android：Activity/Fragment 直接 new 数据库、数据装静态变量、逻辑全塞在回调里、没有 ViewModel、没有网络层、没有测试、没有版本控制、没有签名发布配置。

换句话说：你学会了「API 怎么调」，但还没学「工程怎么组织」和「App 怎么上线」。这两块恰恰是求职和上架的门槛。下面按"知识地图 → 项目欠账 → 分阶段路线 → Java 方向提醒 → 求职与上架"五部分展开。

二、这个项目完全没碰的知识板块

2.1 架构与状态管理（求职面试第一大块）

现状：Fragment 里直接 new DbManager(getContext())，数据、UI、业务逻辑三层混在同一个类里；用户 id 用 MainActivity.currentuserid 这种静态变量传。
知识点为什么必须有
ViewModel + LiveData/StateFlow你现在旋转屏幕、切后台被回收，数据就没了（静态变量除外），Fragment 重建后 onCreateView 重新查库。ViewModel 就是干这个的：让数据活过配置变更。
MVVM / 单向数据流UI 只读状态、只发事件；逻辑在 ViewModel。面试必问"MVC/MVP/MVVM 区别"。
Repository 模式 / 单一数据源(SSOT)以后数据来源会变成"本地库 + 远端接口"，需要一个统一出口决定读哪边、怎么缓存。
依赖注入（Hilt / Dagger）现在到处 new DbManager(context)，测试时没法替换。Hilt 对 Java 支持是完整的。
Navigation 组件替掉手写 replace()，处理返回栈、参数传递、Deep Link。FragmentResult 替代 Fragment 之间互相持有引用。
模块化（多 module）大项目必然要拆 module（feature / core / data），是"资深"与"初级"的分水岭之一。

2.2 数据层的正确姿势

知识点你现在的问题 / 为什么必须补
Room行业事实标准。你手写的 SQLiteOpenHelper 全部能平移过去；Room 自带 @Query 编译期校验、Migration、Flow 响应式查询、事务。
数据库迁移 Migration你的 onUpgrade() 是 drop table 三张表再重建 —— 用户所有数据全丢。正确做法是写 ALTER TABLE 迁移脚本。上架后这是硬要求。
事务 Transaction你的"选课"是两步：insertSelection() + updateSelectedCount()，不在一个事务里。中途失败会造成人数和记录不一致。Room 的 @Transaction 或 beginTransaction()/setTransactionSuccessful()/endTransaction() 解决。
DataStore / SharedPreferences你的语言选择、登录用户 id 全在静态变量里，App 一重启就回到中文、回到登录页。这就是"没有持久化"的典型症状。DataStore 是现在的首选（SharedPreferences 已被官方建议替换）。
文件存储 / Scoped Storage / SAFAndroid 10 起分区存储，WRITE_EXTERNAL_STORAGE 基本作废。getExternalFilesDir()、MediaStore、ACTION_OPEN_DOCUMENT 是必修。
序列化（JSON）Gson / Moshi / kotlinx.serialization，和网络层一体。
数据安全你的密码是明文存库、明文比较（passwd text not null + where passwd=?）。至少要哈希加盐（BCrypt/Argon2）；本地敏感数据用 EncryptedSharedPreferences / Keystore。

2.3 网络与异步（几乎每份 JD 都要求）

现状：整个项目 0 行网络代码，数据全是 MyDbHelper.onCreate() 里写死的 10 条种子。
  • Retrofit + OkHttp：定义接口 → 拿数据；拦截器（统一加 token、打日志、统一错误处理）、超时、重试、缓存。
  • 图片加载 Glide / Coil：列表里加载头像/封面，含内存+磁盘缓存、占位图、圆角变换。
  • 分页 Paging 3：长列表下拉加载，别自己写"。
  • 离线优先 / 缓存策略：网络失败降级读本地，本地写操作排队重试。
  • 异步与线程：你把 db.getAllcourses() 直接放在点击回调里跑，那就是主线程。数据一大就 ANR。Java 方向可用 ExecutorService、Handler/Looper、AsyncTask（已废弃，别学）、RxJava，或直接上 Kotlin 协程。
  • 主线程 / ANR / StrictMode：知道什么绝对不能放主线程，会用 StrictMode 自查。

2.5 工程质量（决定你是"能写"还是"能交付"）

知识点项目状态 / 说明
Git 版本控制项目里没有 .git 这是最基础也最要紧的一条。分支模型（main / feature）、提交规范（Conventional Commits）、Code Review、.gitignore、合并冲突处理。
单元测试零 JUnit + Mockito；只测纯逻辑（比如"冲突检测"算法、学分计算）。app/src/test 目录存在但没写东西。

下面这些不是"代码写错了"，而是每一处都对应一个你还没学的知识点。把它们当成"重构任务"，改完就等于把对应知识练了一遍 —— 比重开一个新 App 学得更快。

四、Java 方向学习路线（4 个阶段，约 8~10 周）

阶段 0 · 先补最不该缺的两件事（3 天）

目标：把项目纳入"工程管理"，养成习惯。这段最便宜、收益最大。

  • Git：git init → 提交现有代码 → 学会 branch / merge / 冲突解决 / 写 .gitignore。以后每次改动都提交。
  • ViewBinding：build.gradle 开启 → 把 findViewById 全换掉。
  • 学会看 Lint：跑一次 ./gradlew lint，把报告里的 warning 逐个看懂（不用全改）。

阶段 1 · 把项目改成"现代架构"（2 周）

目标：掌握 ViewModel 与 Repository，做到旋转屏幕不丢状态、重启能记住登录。

  • ViewModel + LiveData：每个页面一个 ViewModel，数据放进去，UI 只观察。
  • Repository 层：把 DbManager 收敛到 Repository 后面，Fragment 不再直接碰数据库。
  • DataStore：语言、登录态、自动登录。
  • Room：三张表迁到 Room，写 Migration 而不是 drop。
  • Hilt：把 Repository 注入 ViewModel。
  • Navigation 组件：底部导航 + 返回栈交给它管。
  • 三态 UI：Loading / Empty / Error 全补齐。

阶段 2 · 加一层网络，理解"真实 App 的数据从哪来"（2~3 周）

目标：能独立接一个后端接口，并处理网络的不确定性。

  • Retrofit + OkHttp + Gson：把课程列表改成从接口拉（可以自己用 Mocky / 本地 Spring Boot / 免费 API 起一个）。
  • 拦截器：统一加 header、统一解析错误码、打网络日志。
  • Glide / Coil：列表加载图片。
  • 缓存与离线：网络失败读 Room；写操作排队重试。
  • 异步：Java 用 ExecutorService + Handler 回主线程（这一步做完你就会无比想学 Kotlin 协程）。

阶段 3 · 系统能力 + 质量保障（2~3 周）

目标：让 App 具备"真功能"，并开始用测试和工具保证质量。

  • 运行时权限 → 加一个"上传头像"功能（相机 + 相册 + 权限 + 文件）。
  • 通知 + WorkManager → 加"选课成功提醒"、"课程冲突后台校验"。
  • 广播 / ContentProvider → 监听网络变化、读取系统日历把课表写进去。
  • 定位 + 地图（选做）→ 显示教学楼位置。
  • 单元测试 → 给"冲突检测"算法和"学分统计"写 JUnit 测试。
  • UI 测试 → Espresso 测登录与选课主流程。
  • 性能 → LeakCanary 抓泄漏、Layout Inspector 看层级、DiffUtil 优化列表。
  • CI → GitHub Actions：push 自动编译 + 跑测试。

阶段 4 · 发布与上架 + 开始转 Kotlin（2 周，与上阶段可并行）

目标：拿到"已上架 App"这个最硬的求职凭证。

  • 签名：生成 keystore、配置 signingConfigs、妥善备份。
  • R8 / 混淆：开 minifyEnabled，处理 keep 规则。
  • 隐私合规：写隐私政策页、权限用途说明、第三方 SDK 清单。
  • 备案与软著：了解流程（国内上架前置）。
  • 上架：先投 Google Play（流程标准化、文档全）或国内某一家商店走通全流程。
  • 崩溃监控：接 Crashlytics / Bugly，看真实崩溃。
  • 开始学 Kotlin：语法 3 天可上手；重点学 协程（取代线程回调地狱）、扩展函数、空安全、data class。

五、Java 方向的现实提醒（这几点必须提前知道）

1. 有些新东西是"Kotlin 独占"，Java 只能走老路。
能力Java 路线Kotlin 路线
UIXML 布局 + View 体系（你正在做的）Jetpack Compose（只有 Kotlin）
异步ExecutorService / Handler / RxJava（回调地狱）协程（结构化并发，写法接近同步）
状态LiveDataStateFlow / Compose State
依赖注入Hilt 支持完整 ✅Hilt / Koin
数据库Room 支持完整 ✅Room
网络Retrofit 支持完整 ✅Retrofit

结论：Java 完全能做出一个可上架的 App，但 Compose 和协程这两块你拿不到。它们正是现在招聘 JD 里出现频率最高的词。

2. 中文 Android 招聘市场的现状。JD 普遍写"熟悉 Kotlin"、"了解 Jetpack Compose"、"熟悉协程"，纯 Java 岗位在快速萎缩，多见于老项目维护。所以 Java 是你的"过渡船"，不是终点。建议节奏：先用 Java 把阶段 0~3 走完（把 Android 的"道"搞懂，这部分和语言无关），阶段 4 开始学 Kotlin，然后再用 Kotlin 把同一个 App 重写一遍 —— 这一次重写你会快得多。
3. 好消息。你已经在用 attachBaseContext、RecyclerView.ViewHolder、SQLiteOpenHelper 这些"概念型"API，说明你在意"为什么这么写"。这类人转 Kotlin 通常一两周就顺了；反而是只会背 API 的人，换个语言就废。
