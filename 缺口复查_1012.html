一、会崩溃（不修就闪退）

必崩1. 点任意一个筛选按钮，应用直接闪退

位置：CourseHallFragment.java:29 与 :34（方法 filter_class()）

private DbManager db;              // 第25行，字段，从未被赋值 → null
private List<Course> list;         // 第26行，字段，从未被赋值 → null

public void filter_class(String type){
    for (Course c:db.getAllcourses()){   // ← 第29行，db 是 null → 崩
    ...
    list.clear();                        // ← 第34行，list 是 null → 也崩
}

根因是"局部变量遮蔽字段"。onCreateView 里写的是：

DbManager db=new DbManager(getContext());   // 第73行 ← 带了类型声明
List<Course> list=db.getAllcourses();       // 第74行 ← 带了类型声明

带了 DbManager / List<Course> 这两个类型声明，Java 就会**新建两个局部变量**，而不是给字段赋值。于是类里那两个字段一直是 null。方法内部的代码（搜索监听、Adapter）用的是局部变量，所以正常；但 filter_class() 是**另一个方法**，它看不到那两个局部变量，只能用字段 → null → 闪退。

改法（把两行前面的类型声明去掉）：

db   = new DbManager(getContext());   // 去掉"DbManager "
list = db.getAllcourses();            // 去掉"List<Course> "

必崩2. "全部"按钮点了列表必空，切语言后 6 个筛选全废

位置：CourseHallFragment.java:30

if(c.type.equals(type) || c.type.equals("全部"))   // ← 后面的判断主体写反了

点"全部"时传进来的 type 是"全部"，而没有任何一门课程的 type 字段值是"全部"（库里存的是"专业课 / 公共课 / 选修课"）→ 两个条件都不成立 → 结果 0 条，列表被清空。

应改为：if(c.type.equals(type) || type.equals(getString(R.string.str42)))

还有一个连带问题：这个比较是拿数据库里的中文字段去比当前语言的资源字符串。切到 EN 后 str44 变成 "Major"，永远匹配不上 → 6 个筛选按钮全部失效。要么给库里存英文枚举值，要么用中文常量比较。

界面塌陷3. 搜索框会被压成 0 宽，几乎看不见

位置：acti_course.xml:25-34

<LinearLayout android:layout_width="wrap_content" ...>   <!-- 第26行 父容器是 wrap_content -->
    <EditText android:layout_width="0dp"
              android:layout_weight="1" ... />             <!-- 第31-33行 -->

水平 LinearLayout 的宽度是 wrap_content 时，它没有"剩余空间"可分，width=0dp + weight=1 的 EditText 会被算成 0 宽。而它右边那个"搜索"按钮是 wrap_content，会正常显示 —— 结果就是"有按钮、没输入框"。

改法：第26行的 layout_width="wrap_content" 改成 match_parent。

二、功能断点（有入口、没反应）

P14. 语言切换仍然失败（这条你问过两次了，根因没变）

位置：MainActivity.java:27-31、LoginActivity.java:21-25

Configuration config = new Configuration();      // ← 空配置，把密度/字体缩放全重置了
config.setLocale(locale);
getResources().updateConfiguration(config, getResources().getDisplayMetrics());

三件事叠在一起：① new Configuration() 是个全默认的空对象；② updateConfiguration 在 Android 7.0 之后已被废弃，对已经创建好的 Resources 基本不生效；③ 你用的是 AppCompatActivity（AppCompat 1.6.1），它内部持有自己的 Configuration，会把你在 onCreate 里的改动盖回去。recreate() 重建后又走同一条路，所以永远是"点了没反应"。

推荐改法 —— 两个 Activity 都加 attachBaseContext()：

@Override
protected void attachBaseContext(Context newBase) {
    Locale locale = new Locale(MainActivity.lang);
    Locale.setDefault(locale);
    Configuration cfg = new Configuration(newBase.getResources().getConfiguration()); // 克隆，不是 new()
    cfg.setLocale(locale);
    super.attachBaseContext(newBase.createConfigurationContext(cfg));                // 包一层
}

加上之后，onCreate 里那 5 行改配置的代码要删掉。attachBaseContext 在 onCreate 之前执行，那时候资源已经是目标语言，setContentView、Fragment、getString() 全都自动生效。

备选：AppCompatDelegate.setApplicationLocales(LocaleListCompat.forLanguageTags("en"))，会自动重建 Activity，但要补 res/xml/locales_config.xml 和 Manifest 的 android:localeConfig（现在这两个都没有）。
