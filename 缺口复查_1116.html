三、🔴 必崩 / 明显失效（P0）

1. 「已选」「冲突」两个筛选按钮，一点就把列表清空

文件：CourseHallFragment.java:174-175

两个按钮仍然把 str46("已选") / str47("冲突") 传给按课程类型过滤的 filter_class()。数据库里 type 只有「专业课 / 公共课 / 选修课」三种，永远匹配不到 → 命中 0 条 → 列表变空白。

「已选」：直接用现成的 db.searchclass(userid)，它返回的就是这个用户已选的课。
「冲突」：把已选课程两两比对 Course.time 是否相同。这个方法你已经在 47–55 行注释里起了个头，补完即可；不想做就把它从界面上撤掉。

2. 我的课表点"选课"，会把已选人数越点越大

文件：MyCoursesFragment.java:36-38

课表里的课程本来就是已选的，insertSelection 被 CONFLICT_IGNORE 静默忽略掉没插进去，但下一行 updateSelectedCount(courseid,+1) 是无条件执行的 → 数据库里 selectedCount 每点一次 +1，选课大厅的余量就少一个。

而且课表里本来就不该有"选课"按钮 —— 它复用了选课大厅的 Adapter，两个按钮都绑上了。要么给 Adapter 加个开关（课表模式只显示"退课"），要么把 onSelect 改成空实现。

3. 语言切换仍然失败（你问过两次的这个问题）

文件：MainActivity.java:27-31、LoginActivity.java:21-25

两处仍是 new Configuration()（空对象）+ getResources().updateConfiguration()，且写在 super.onCreate() 之后。在 AppCompat 1.6.1 环境下这条路走不通：AppCompat 有自己的 Context 包装和 Configuration，你在外层改的会被它无视；空 Configuration 又会被系统判为"不完整变更"而拒绝应用。

唯一有效的改法：把改配置的代码从 onCreate 挪到 attachBaseContext(Context newBase)，并用 new Configuration(newBase.getResources().getConfiguration())（克隆当前配置）+ newBase.createConfigurationContext(config) 包一层。MainActivity 和 LoginActivity 两个都要加，加完 onCreate 里那 5 行删掉。

4. 「成绩查询」Tab 点了停在选课大厅

文件：bottom_nav_menu.xml:5、MainActivity.java:58-72

菜单里有 nav_scores，但 MainActivity 只处理了 nav_my / nav_profile，其余落进 else → 停在选课大厅。工程里没有对应的 Fragment、布局，DbManager 也没有查成绩的方法。
